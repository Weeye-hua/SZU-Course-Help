# 深大抢课助手 3.7.0 使用手册

- 适用项目：SZU Course Help
- 下载页面：https://github.com/Weeye-hua/SZU-Course-Help/releases/latest
- 问题反馈：https://github.com/Weeye-hua/SZU-Course-Help/issues

> 本项目是非官方工具，与深圳大学及其选课系统运营方无隶属或授权关系。请遵守学校规定。本科生预选阶段禁止自动抢课；研究生仅在学校明确允许选课的开放时间与策略下启用任务。

## 一、选择下载包

在最新 Release 的 Assets 中按系统下载：

- Windows 10/11 64 位：`SZU-Course-Help-v3.7.0-windows-x64.zip`
- macOS Apple 芯片：`SZU-Course-Help-v3.7.0-macos-arm64.zip`
- macOS Intel 芯片：`SZU-Course-Help-v3.7.0-macos-x64.zip`
- Linux 64 位：`SZU-Course-Help-v3.7.0-linux-x64.zip`

必须先完整解压 ZIP。不要在压缩包预览窗口中运行，也不要只拖出主程序，否则 OCR 模型和依赖文件可能缺失。普通用户不要下载 GitHub 自动生成的 Source code 压缩包。

发布包包含可执行程序、平台启动脚本、Markdown/PDF 使用手册、更新记录和许可证。本项目不提供单独的 SHA256 文件。

## 二、按系统启动

### Windows

1. 右键 ZIP，选择“全部解压缩”。
2. 双击 `启动抢课助手.bat`，也可运行 `SZU-Course-Help.exe`。
3. 保持终端窗口开启，关闭终端会停止本地服务。

SmartScreen 可能提示未知发布者，因为当前程序没有商业代码签名。请先确认文件来自本项目官方 Release，再决定是否运行。

### macOS

- Apple M 系列芯片下载 `macos-arm64`。
- Intel 处理器下载 `macos-x64`。

解压后双击 `启动抢课助手.command`。若 Gatekeeper 阻止运行，可在“系统设置 - 隐私与安全性”中确认来源后允许；也可以在该目录打开终端执行：

```bash
chmod +x ./启动抢课助手.command ./SZU-Course-Help
xattr -dr com.apple.quarantine .
./启动抢课助手.command
```

不要为了运行来源不明的副本而关闭整个系统的安全功能。

### Linux

在解压目录执行：

```bash
chmod +x ./启动抢课助手.sh ./SZU-Course-Help
./启动抢课助手.sh
```

Linux 包在 Ubuntu 22.04 x64 构建，不保证兼容过旧的 glibc。部分发行版直接运行打包程序可能失败，此时建议按“开发者源码运行”使用 Python 3.13 或 3.14。

## 三、第一次启动和登录

1. 终端先选择 `1 本科生` 或 `2 研究生`（回车默认本科生），再输入自己的学号，只允许 6 至 12 位数字。切换模式需要退出并重新启动程序。
2. 程序读取或生成本机 Ed25519 身份，显示学号、密钥指纹和 Card Key V3。
3. 在“是否进入选课系统”处输入 `Y`。
4. 浏览器会打开终端打印的 `http://127.0.0.1:端口/login`；没有自动打开时手动复制该地址。
5. 登录页已预填学号和 Card Key。输入深圳大学选课系统密码。
6. 本科生按验证码上方四个汉字的顺序点击图片；研究生填写四位字母或数字验证码，也可使用识别按钮并核对结果，然后登录。

Card Key 只在本机验证，不发送给学校。学校密码只保存在当前程序进程内存中，用于会话过期后的 OCR 自动重登录，不写入 SQLite、浏览器存储或会话文件。关闭程序或开发重载后需要重新手动登录。

若学校没有开放验证码接口，页面会显示“当前时段暂无验证码”并停止本次加载，不会一直转圈或后台循环。等待学校开放或维护结束后，再点击“重新获取验证码”。这不表示密码或 Card Key 错误。

## 四、选课阶段

### 研究生开放状态

研究生使用独立系统，不套用本科生“预选/复选/补选”名称。程序读取学校服务器时间、轮次、学期、开放起止时间、开放标志和选课策略。仅在开放标志有效、当前时间处于开放区间且策略允许选课时启用启动入口；“不可选可退”、已结束、字段不完整或无法读取状态时均禁止启动。助手本身不提供退课。

启动或恢复前会再次确认状态，不需要按每学期手动修改日期。登录成功或能查看课程不等于当前允许选课。

### 本科生阶段

程序不使用每学期写死的日期，而是读取学校返回的批次代码和批次名称。

### 预选

- 可以浏览课程和整理本地清单。
- 禁止启动自动抢课，因为预选结果由学校抽签。

### 复选、正选、补选或补退选

- 名称明确匹配允许阶段后，页面才会开放启动入口。
- 用户必须再次勾选确认。
- 后端在真正创建任务前还会重新向学校确认批次。

### 未开放、已结束或未知

- 课程目录可能无法读取，页面会区分未开放、网络失败、超时和异常响应。
- 本地清单与安全课程缓存会保留。
- 批次无法确认时一律禁止启动，不会根据本地时间猜测。

学校可能先显示“正选”，但具体开放分钟尚未到。若第一次提交明确返回“当前时间不在选课开放时间范围内”，程序只提交一次并自动暂停；实际开放后再点击继续。

## 五、课程目录、校区和缓存

### 研究生目录

- 方案内课程和跨专业课程可在学校允许时加入本地清单；跨专业目录为空可能表示当前没有对该账号开放的课程。
- 开课查询用于浏览，可按关键词、院系及是否属于方案筛选。该入口严格只读，即使有空位也不能直接加入清单，不表示该账号有选课资格。
- 已选课程、学分统计和课表读取学校结果，不提供“我的方案”维护、退课、本科生校区切换或 WebVPN。
- 研究生缓存按账号、轮次、目录、分页及筛选条件隔离，只缓存成功查询结果；缓存只读，选课请使用实时方案内或跨专业目录。

### 本科生目录和校区

左侧或手机顶部可切换本班推荐、方案内、方案外、校公选、体育和慕课。课程组默认折叠，只有用户点击后才展开教学班。

- “可加入”：可以放入本地清单。
- “已满”：可以加入清单，开放阶段持续等待空位。
- “时间冲突”或“已选”：不能加入。
- “隐藏冲突”和“隐藏已满”只改变当前浏览器显示，已选教学班仍保留可见；筛选后没有可见教学班的课程会连同选项卡一起隐藏，顶部会显示本页筛选后的可见课程数。
- 辅修课程当前明确禁用，请使用学校官方系统处理。

课程工具栏支持粤海、丽湖、深大附属医院、技术大学、香港和深理光明六个校区。首次登录采用学校返回的默认校区；手动切换后，批次刷新和 OCR 重登录不会重置它。每门清单课程保存加入时的校区，之后切换目录不会改变其提交参数。

### 本科生缓存模式

- `TJKC` 和 `FANKC` 完整读取成功后，会保存全目录只读缓存。
- 缓存按终端学号摘要、批次、校区和课程类型严格隔离，不保存明文学号。
- 未登录、无批次或非开放期只读缓存时，不会偷偷访问学校，也不会回退显示其他账号的数据。
- 登录有效时，缓存模式先显示本地结果，并每 30 秒尝试一次明确的实时刷新；失败或空响应不会清空现有内容。
- 缓存课程不能直接加入清单；需要切回实时目录确认最新冲突、容量和已选状态。

## 六、我的课程、学分和课表

“我的课程”只读取学校当前已选课程，并可叠加显示清单中的待选课程。页面分别统计学校已选学分、清单待选学分和合计学分；这些数字只用于查看，不会触发自动退课。

课表按周一至周日、1 至 14 节显示：

- 只要学校文字中包含星期和具体节次，就会进入网格。
- 多星期、多时段、不同周次以及单双周会分别展示；周次不阻止课程排入。
- 真实重叠的片段才会并排，长课程名称、地点和教师会换行并扩展行高。
- 只有缺少星期、缺少具体节次或节次超出范围的课程，才进入下方未安排列表。

该页面不会执行选课、退课或修改清单。

研究生课表优先读取学校结构化星期和节次，不使用本科生固定作息钟点。详细课表暂不可用时，会退回已选课程中的文字安排并显示提醒；请刷新或在学校官网核对。没有具体节次的课程保留在未安排列表中，不会丢失。

## 七、启动、暂停、编辑、继续和停止

“加入清单”不会立刻向学校提交。只有在允许阶段、完成二次确认并点击启动后，后台任务才开始。

- 每轮对每门已启用课程各提交一次，避免一门课长期独占循环。
- 满员是明确的可重试状态，会持续保留；学校提示成功或“已经选过”后仍需回查已选列表，冲突、超学分等按学校明确响应分类。
- 点击“暂停”后可能短暂显示“正在暂停”，表示当前学校请求尚未结束，此时仍不能编辑活动课程。
- 显示“已暂停”后，可以新增、移除、重新排队、打开或关闭单门自动抢课，并调整优选分组和组内优先级。
- 继续前以及每一轮请求前，后台都会重新读取 SQLite：新增课程入队、移除或关闭的课程出队，尝试次数和失败次数继续保留。
- 优先级只控制同组课程的尝试顺序，不会自动退选、替换或升级任何已选课程。
- 移除最后一门活动课程会使任务有序结束。
- “停止抢课”会结束当前任务但保留本地清单；之后重新启动仍需确认阶段。

爆发模式转一般模式、一般模式转扫描模式的业务失败阈值可以分别设置为 1 至 1,000,000 次，默认值为 5 次和累计 10 次。勾选某一级的“无限次”后，该模式不会因业务失败自动降级；两个选项互不影响。设置在当前程序进程内即时生效，刷新页面仍会从后台恢复，重新启动程序后恢复默认值。网络异常和学校 5xx 响应继续使用独立保护逻辑，不计入业务失败阈值。

未知学校响应按课程分别计数，默认连续 2000 次才保护性暂停；中间收到任何已识别响应会清零该课程计数。可在启动前设置 `COURSE_SELECT_UNKNOWN_RESPONSE_LIMIT`，非法值、零或负数会回退到 2000。不建议关闭保护。

学校提交响应不是最终成功凭据。收到“添加选课志愿成功”或“已经选过”后，程序会用“我的课程”相同的学校已选接口最多回查 3 次，并按完整教学班 ID 精确匹配：

- 精确匹配后才把本地清单写为成功；同名课程、相同教师或相近时间均不能替代 ID 核验。
- 已选列表有效但目标教学班暂未出现时，课程保持待处理并继续尝试，以兼容学校写入延迟或提交假成功。
- 核验时登录过期会进入 OCR 自动重登录；核验接口持续超时、数据畸形或缺少教学班 ID 时会保护性暂停，不会盲目继续提交。
- 页面会显示“正在核对学校已选课程”“尚未出现该教学班”或具体暂停原因；可同时刷新“我的课程”核对学校结果。

## 八、会话过期与 OCR 自动重登录

学校会话可能在长时间运行后过期。程序检测到明确过期信号时会：

1. 按当前模式获取新的验证码。
2. 本科生使用 `ddddocr` 识别候选文字和坐标，可选 PaddleOCR 识别顶部目标文字；研究生使用 `ddddocr` 识别四位字符。
3. 使用当前进程内存中的学号和密码重新执行学校登录协议。
4. 原子更新 token、Cookie 与批次。
5. 在工作台显示恢复状态，并继续未完成任务。

每次恢复最多尝试 50 张验证码。学校明确关闭验证码接口时会立即停止，不会请求满 50 次。本科生验证码接口若连续 3 次返回缺失必要 Cookie、畸形 token 等结构性异常，也会提前停止并提示手动登录；成功取得一次完整验证码响应会立即清零该计数，因此普通 OCR 识别失败仍保留完整的 50 次预算。研究生遇到无法完整读取的验证码或开放状态同样会明确报错，不会把缺失字段当成登录成功。多个请求同时发现过期时，只运行一个 OCR 恢复；活动任务的保活也由单一会话管理器协调。

本科生自动重登录的验证码 token、图片和登录提交使用同一轮干净 Cookie：登录请求只携带本轮验证码下发的 `route` 与 `insert_cookie`，不会拼接已经过期的学校会话 Cookie。WebVPN 只读请求在省略学校会话 Cookie 时仍会保留独立的网关认证 Cookie。研究生使用独立 HTTPS 入口和当前验证码轮次的 Cookie，不混用本科生会话。

启动时会真实初始化 OCR。若提示依赖不可用，手动首次登录仍可使用，但会话过期后需要手动登录。v3.7.0 继续兼容 `ddddocr 1.6.1` 的 `ddddocr.core`、顶层新引擎和旧 `DdddOcr` API；官方 Release 构建和 Python 3.13/3.14 CI 均执行初始化测试。

## 九、Release 数据目录和升级迁移

Release 不再把清单和密钥留在每个解压目录中：

- Windows：`%APPDATA%\SZU-Course-Help\`
- macOS：`~/Library/Application Support/SZU-Course-Help/`
- Linux：`${XDG_DATA_HOME:-~/.local/share}/SZU-Course-Help/`

研究生数据使用上述目录的 `graduate` 子目录，清单位于 `graduate/accounts/<账号哈希>/`。本科生与研究生不互相读取清单或迁移对方数据；更换研究生账号也不会显示上一个账号的清单。`COURSE_SELECT_DB_PATH` 只控制本科生清单，自定义研究生位置请使用 `COURSE_SELECT_DATA_DIR`。

Card Key 私钥位于当前模式数据目录的 `keys` 子目录。本科生首次启动新版本时，程序会保守查找当前安装目录和同级旧版本目录：

- 只迁移 `course_enroll.db`、匹配的 Ed25519 公私钥和通过账号隔离校验的 v2 课程缓存。
- SQLite 使用 backup API 复制，包含 WAL 内容并执行完整性检查。
- 只复制、不移动，绝不覆盖目标已有文件；旧版本仍可回滚。
- 多个旧目录并存时由终端选择；非交互启动不猜测，可设置 `COURSE_SELECT_LEGACY_DATA_DIR`。
- 不迁移密码、token、Cookie、验证码图片、日志或不安全的旧缓存。

源码运行仍默认使用源码目录。`COURSE_SELECT_DATA_DIR`、`COURSE_SELECT_DB_PATH` 和 `COURSE_SELECT_KEY_DIR` 可显式覆盖默认位置。

卸载前请先退出程序。只删除解压目录不会删除平台数据目录；若要彻底清除，请确认不再需要清单和 Card Key 身份后再删除对应用户数据目录。私钥一旦删除，旧 Card Key 无法继续验证。

## 十、WebVPN 只读备用入口

本节仅适用于本科生模式；研究生使用独立学校入口，不提供此选项。

主站只读查询短暂不可用时，可以完成 WebVPN 统一认证。程序会启动本机 Chromium/Chrome/Edge 的一次性受控窗口，获取所需网关 Cookie 后关闭并删除临时浏览器配置。

- WebVPN 只参与登录与只读课程/已选信息查询。
- 选课提交固定使用学校主站且不跨后端重试；本版不提供自动退课。
- 程序不保存浏览器密码，也不注入持久化浏览器资料。
- 没有完整 WebVPN Cookie 时不会假装回退成功；主站仍是唯一可用入口。

## 十一、常见问题

### 浏览器没有自动打开

保持终端开启，把终端打印的本地地址复制到 Chrome、Edge、Firefox 或 Safari。端口 8000 被占用时程序会自动尝试后续端口，以终端地址为准。

### 页面显示课程目录读取失败

可能是学校拥堵、超时、非开放期或响应格式变化。点击“刷新课程”。已有成功结果时页面会尽量保留；也可以显式开启当前账号范围内的缓存模式。

### 暂停后仍不能编辑

“正在暂停”表示请求还未结束；等待变成“已暂停”。此时新增、移除、开关、重试和优先级控件会启用。如果另一个浏览器页面修改了清单，进度轮询会按队列版本自动重新加载。

### 为什么正式开放后抢不到仍会暂停

满员不会触发 2000 次未知响应阈值。只有连续无法识别的学校响应、连续网络异常、明确未开放、会话恢复失败、选课结果无法可靠核验、本地状态写入失败、用户暂停或停止等保护条件才会暂停，清单和计数会保留。

### 为什么学校提示成功后仍显示“正在核对”

学校提交接口偶尔会先返回成功但没有真正写入。助手必须在学校已选列表中看到完全相同的教学班 ID 才确认抢到；短暂同步延迟会回查 3 次，仍未出现则继续尝试。若已选接口本身不可用，任务会暂停而不是猜测结果。

### 为什么升级后没有自动迁移旧数据

检查终端是否提示多个候选目录。程序不会猜测，应选择正确目录或设置 `COURSE_SELECT_LEGACY_DATA_DIR`。目标已有数据库或密钥时不会覆盖；旧目录也不会被自动删除。

### 页面还是旧 UI

确认启动的是当前版本，关闭旧页面后重新打开本次终端打印的 `/login` 地址。开发重载会清空学校会话，需要重新手动登录。

## 十二、安全提醒

- 只从 https://github.com/Weeye-hua/SZU-Course-Help/releases 下载。
- 不要公开学号、密码、Cookie、token、验证码截图、Card Key、PEM 密钥、SQLite 数据库或完整日志。
- 本地服务只监听 `127.0.0.1`；不要通过端口转发或反向代理暴露到局域网或公网。
- 学校登录与选课接口的传输安全能力受上游系统限制。
- 关键选课结果始终以学校官方系统为准。

```powershell
git clone git@github.com:Weeye-hua/SZU-Course-Help.git
```
